⚡ Quick Start
SHELL 
# 1. Build the fat JAR
mvn package -q -DskipTests

# 2. Create a PDF directly
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --title  "Hello World" \
  --text   "My first generated PDF." \
  --output hello.pdf

# 3. Extract text back out
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract --input hello.pdf

# 4. List available printers
java -jar target/pdf-creator-1.0-SNAPSHOT.jar --list-printers

# 5. Run the full test suite
./run-tests.sh
Direct Mode

Generate a PDF from a title, author, and body text with no template file required. Best for meeting notes, quick reports, and ad-hoc documents.

01
Inline Title & Text
Pass the document body directly on the command line

Supply all content as CLI arguments. Multi-paragraph body text uses \n\n as a paragraph separator. The renderer word-wraps automatically.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --title  "Meeting Notes — Q1 2026" \
  --author "Jane Smith" \
  --text   "Attendees: Jane Smith, Robert Jones, Priya Patel.\n\nKey decisions: approved Q1 budget, deferred platform migration to Q2.\n\nActions: Jane to circulate revised budget by Friday." \
  --output output/01-direct-inline.pdf
✓ Produces: 01-direct-inline.pdf — single page with heading, author line, and wrapped body paragraphs
02
Text from File
Read body content from a .txt file on disk

Point --text-file at a plain text file. Use blank lines for paragraph breaks. Auto-pagination kicks in if text overflows a page.

PLAIN TEXT — body.txt 
This is paragraph one. It demonstrates proper word-wrapping
behaviour across the full usable page width.

This is paragraph two. A blank line produces a paragraph break.

This is paragraph three. A new page starts when the cursor
reaches the bottom margin.
SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --title     "Report from File" \
  --text-file body.txt \
  --output    output/02-direct-from-file.pdf
✓ Produces: 02-direct-from-file.pdf — paginated document from file content
03
Custom Config Preset
Override fonts, margins, and colors with a named config

Each config preset in configs/pdf-configs.json defines a complete visual style. Available presets: default, report, letter, compact, banking, dark.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --config-id report \
  --title     "Q4 Executive Summary" \
  --text      "Revenue exceeded targets by 12% in Q4. Operating costs remained within budget." \
  --output    output/03-direct-report-config.pdf
ℹ The report preset uses wider margins (72pt), larger title font (24pt), and dark blue title color (#003366) vs the 50pt margins and 20pt titles of the default preset.
✓ Produces: 03-direct-report-config.pdf — styled with the report preset's fonts and spacing

Template Mode

Combine a template definition (templates/pdf-templates.json) with a JSON data file. Templates define layout, branding, section types, and placeholder keys. Data files supply the runtime values.

04
Bank Statement
Columns layout · transaction table · summary · footer with page numbers

The most feature-rich template. Exercises the full rendering pipeline: per-page header band, two-column address/account layout, opening/closing balance summary, 19-row transaction table with alternating row colors and header repeat on new pages, regulatory notice box, and configurable footer with page numbers on every page.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --template-id bank-statement \
  --data-file   data/statements/CUST-001.json \
  --output      output/04-bank-statement-cust001.pdf
JSON — data/statements/CUST-001.json (excerpt) 
{
  "bank_name":       "National Bank plc",
  "customer_name":   "Jane Smith",
  "account_no":      "12345678",
  "sort_code":       "20-00-00",
  "opening_balance": "£4,210.00",
  "closing_balance": "£5,861.55",
  "transactions": [
    { "date": "01 Feb", "type": "BAL FWD", "description": "Opening Balance",       "credit": "4,210.00", "debit": "" },
    { "date": "03 Feb", "type": "BACS",    "description": "EMPLOYER PAYROLL LTD",     "credit": "3,200.00", "debit": "" },
    { "date": "03 Feb", "type": "DD",      "description": "THAMES WATER UTILITIES",    "credit": "",        "debit": "42.50" }
    // ... 19 transactions total
  ]
}
✓ Produces: 04-bank-statement-cust001.pdf — 2 pages with header band, columns, table, notice

07
Missing Placeholder Warning
Graceful handling — renders successfully with a warning, not a crash

If the data file omits a key that a template references, the placeholder is left blank in the output and a warning is printed to stderr. The render does not throw an exception — partial data still produces a valid PDF.

⚠ Expected stderr: Warning: Unresolved placeholders (no value in data file): [closing_balance]. The PDF is still written to disk.
✓ Produces: 07-missing-placeholder.pdf — renders with blank where the missing value would appear
Batch Mode

Generate thousands of PDFs in parallel from a directory of JSON files or a CSV row-per-record. A shared RenderPipeline is reused across jobs; each job gets its own PDDocument.

08
Directory Source — Parallel
One JSON file per customer → one PDF each, 4 threads
SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --batch \
  --template-id bank-statement \
  --data-dir    data/statements/ \
  --output-dir  output/batch-statements/ \
  --threads     4
JAVA — programmatic API 
RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json", "configs/pdf-configs.json");

List<BatchJob> jobs = new DirectoryBatchJobFactory(
    "bank-statement", "data/statements", "output/batch-statements"
).createJobs();

List<BatchResult> results = new BatchRunner(pipeline, 4).run(jobs);
long ok = results.stream().filter(BatchResult::isSuccess).count();
System.out.printf("%d OK, %d FAILED%n", ok, results.size() - ok);
✓ Produces: CUST-001.pdf, CUST-002.pdf in output/batch-statements/ — generated in parallel
09
CSV Source — Parallel
One CSV row per customer → one PDF each, 3 threads

When each document only needs scalar data (no transaction tables), a CSV is more convenient than individual JSON files. Each row becomes one InMemoryDataSource internally. Column headers become data keys. Use --ref-col and --out-col to specify which columns hold the reference ID and output filename.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --batch \
  --template-id notification-letter \
  --csv-file    data/notifications.csv \
  --output-dir  output/batch-notifications/ \
  --ref-col     ref_id \
  --out-col     output_file \
  --threads     3
✓ Produces: NOTIF-001.pdf, NOTIF-002.pdf, NOTIF-003.pdf in output/batch-notifications/

✓ Same output as scenario 08 — files produced sequentially rather than in parallel
Programmatic API

Use RenderPipeline directly from Java when data comes from a database, REST API, or is assembled in memory — with no intermediate files.

11
InMemoryDataSource
Build DocumentData in code — no files, no network, no database
JAVA — full example 
import com.pdfcreator.datasource.*;
import com.pdfcreator.pipeline.RenderPipeline;
import java.util.*;

List<Map<String, String>> txns = List.of(
    Map.of("date", "01 Mar", "type", "SO",   "description", "RENT PAYMENT",   "debit", "950.00",  "credit", ""),
    Map.of("date", "03 Mar", "type", "BACS", "description", "SALARY ACME LTD", "debit", "",        "credit", "3200.00")
);

DocumentData data = new DocumentData.Builder()
    .scalar("bank_name",       "Test Bank plc")
    .scalar("customer_name",   "Test Customer")
    .scalar("opening_balance", "£2,000.00")
    .scalar("closing_balance", "£3,784.66")
    .list("transactions", txns)
    .build();

new RenderPipeline("templates/pdf-templates.json", "configs/pdf-configs.json")
    .render("bank-statement",
            new InMemoryDataSource(data, "test-customer"),
            "output/11-inmemory-datasource.pdf");
💡 For database-backed generation, replace InMemoryDataSource with JdbcDataSource. The pipeline.render() call stays identical.
✓ Produces: 11-inmemory-datasource.pdf — full bank statement rendered from in-memory data
Error Handling

Both failure modes throw clearly typed exceptions. In batch mode, failures are isolated per job — one bad job does not abort the run.

12
Missing Data File
Expects IOException — file not found
JAVA — catching IOException 
try {
    pipeline.render("bank-statement",
        new JsonFileDataSource("data/does-not-exist.json"),
        "output/12-should-not-be-created.pdf");
} catch (IOException e) {
    // ✓ Expected: "Data file not found: data/does-not-exist.json"

}

Extraction

Read back what is inside any PDF — text content with page ranges and metadata, or embedded raster images filtered by size, format, and page range. Password-protected PDFs are fully supported.

15
Extract Text
Pull all text from a PDF with metadata, page ranges, and whitespace control

Uses PDFBox's PDFTextStripper with position-based sorting. Supports page range selection, whitespace normalisation, and full document metadata extraction (title, author, subject, keywords, page count).

SHELL — CLI 
# Extract all text, print to stdout
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract --input report.pdf

# Pages 2–4 only, save to a file
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract --input report.pdf \
  --start-page 2 --end-page 4 --output extracted.txt

# Also print document metadata (title, author, page count ...)
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract --input report.pdf --include-metadata
FlagDefaultDescription
--inputrequiredPath to the source PDF
--outputstdoutWrite extracted text to this file instead of stdout
--start-page1First page to extract (1-based)
--end-pagelastLast page to extract (1-based, inclusive)
--include-metadataoffPrint title, author, subject, keywords, and page count before the text
--normalize-whitespaceoffCollapse multiple blank lines and trim trailing spaces
--passwordnonePassword for encrypted PDFs
JAVA — programmatic API 
import com.pdfcreator.extractor.*;

ExtractionOptions opts = new ExtractionOptions.Builder()
    .startPage(1).endPage(3)
    .includeMetadata(true)
    .normalizeWhitespace(true)
    .build();

ExtractionResult result = new PdfTextExtractor().extract("report.pdf", opts);

System.out.println(result.getText());
result.getMetadata().forEach((k, v) -> System.out.printf("%s: %s%n", k, v));
✓ ExtractionResult provides getText(), getMetadata(), and getPageCount()
16
Extract Images
Save all embedded raster images to disk with size filtering and format control

Uses PDFBox's PDImageXObject API with recursive form-XObject traversal. Stencil (1-bit mask) images are skipped. Minimum dimension filtering eliminates tiny decorative elements. JPEG images with transparency are composited on a white background before encoding. Output files are named page1-img0.png, page1-img1.png, etc.

SHELL — CLI 
# Extract all images to the default directory (extracted-images/)
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract-images --input report.pdf

# JPEG format, min 100×100 px, pages 1–3, custom output dir
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract-images --input report.pdf \
  --output-dir  output/images/ \
  --img-format  jpg \
  --min-width   100 \
  --min-height  100 \
  --start-page  1 \
  --end-page    3
FlagDefaultDescription
--inputrequiredPath to the source PDF
--output-dirextracted-images/Directory to write image files into (created if absent)
--img-formatpngpng or jpg
--min-width10Skip images narrower than this many pixels
--min-height10Skip images shorter than this many pixels
--start-page1First page to scan (1-based)
--end-pagelastLast page to scan (1-based, inclusive)
--passwordnonePassword for encrypted PDFs
JAVA — programmatic API 
import com.pdfcreator.extractor.*;
import java.nio.file.*;

PdfImageExtractor extractor = new PdfImageExtractor();

// Extract everything into a directory in one call
extractor.extractToDirectory("report.pdf", "output/images/",
    ImageExtractionOptions.defaults());

// Or work with images in memory
ImageExtractionOptions opts = new ImageExtractionOptions.Builder()
    .minWidth(100).minHeight(100)
    .preferredFormat("jpg")
    .startPage(1).endPage(3)
    .build();

List<ExtractedImage> images = extractor.extract("report.pdf", opts);
for (ExtractedImage img : images) {
    System.out.printf("%s — %dx%d px, %d bytes%n",
        img.getSuggestedName(), img.getWidth(), img.getHeight(), img.getSizeBytes());
    Files.write(Path.of(img.getSuggestedName()), img.getData());
}
✓ Each ExtractedImage carries ready-to-write getData() bytes, dimensions, format, page number, and getSuggestedName()
17
Password-Protected PDFs
Decrypt on the fly — works for text extraction, image extraction, merge, and split

All extraction and manipulation operations accept an optional --password flag. PDFBox 3.x API: Loader.loadPDF(file, password) — the String overload, not byte[]. A missing or wrong password throws a typed PasswordRequiredException (extends IOException) with a wasPasswordProvided() flag for targeted error messages.

SHELL — CLI 
# Extract text from an encrypted PDF
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract --input protected.pdf --password secret123

# Extract images from an encrypted PDF
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --extract-images --input protected.pdf \
  --password secret123 --output-dir images/
JAVA — catching PasswordRequiredException 
import com.pdfcreator.extractor.*;

try {
    ExtractionResult result = new PdfTextExtractor()
        .extract("protected.pdf", "secret123");
    System.out.println(result.getText());

} catch (PasswordRequiredException e) {
    if (e.wasPasswordProvided()) {
        System.err.println("Wrong password for: " + e.getMessage());
    } else {
        System.err.println("Password required for: " + e.getMessage());
    }
}
⚠ A PDF can be print-locked or content-locked even when it opens without a password. Text extraction checks canExtractContent() and printing checks canPrint(). Both throw PasswordRequiredException with wasPasswordProvided()=false if permission is denied.
Manipulation

Combine multiple PDFs into one, or divide a single PDF into several — with full support for password-protected inputs and all three split strategies.

18
Merge PDFs
Append two or more PDFs into a single output file

Uses PDFMergerUtility.appendDocument(destination, source) — the correct PDFBox 3.x merge API (addSource() and mergeDocuments() were removed in PDFBox 3). Pages, fonts, images, and colour spaces are deep-copied so each output file is fully self-contained. Document metadata is copied from the first input by default.

SHELL — CLI 
# Merge three PDFs
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --merge \
  --inputs jan.pdf,feb.pdf,mar.pdf \
  --output q1-combined.pdf

# Mix plain and password-protected inputs
# --passwords aligns with --inputs; use empty string for unprotected entries
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --merge \
  --inputs    open.pdf,protected.pdf,also-open.pdf \
  --passwords ,mypassword, \
  --output    merged.pdf

# Skip copying metadata from the first input
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --merge --inputs a.pdf,b.pdf --output out.pdf --no-copy-meta
FlagDefaultDescription
--inputsrequiredComma-separated list of input PDF paths (minimum 2). Order determines page order in output.
--outputmerged.pdfOutput file path
--passwordsnoneComma-separated passwords aligned with --inputs. Use empty string for unprotected inputs: ,secret,
--no-copy-metaoffDo not copy title/author/subject from the first input to the output
JAVA — programmatic API 
import com.pdfcreator.manipulator.*;

MergeOptions opts = new MergeOptions.Builder()
    .addInput("jan.pdf")
    .addInput("feb.pdf")
    .addInput("mar-protected.pdf", "secret")  // password overload
    .output("q1-combined.pdf")
    .copyMetadataFromFirst(true)
    .build();

new PdfManipulator().merge(opts);
ℹ Password-protected inputs are opened via Loader.loadPDF(file, password) and passed directly to appendDocument() as open PDDocument objects — no byte-array serialisation needed.
✓ Produces a single merged PDF. Page count equals the sum of all input pages.
19
Split PDF
Three strategies — every N pages · into N equal parts · explicit page ranges

Uses PDDocument.importPage(PDPage) — the PDFBox 3.x deep-copy API — so each output file is fully self-contained with its own resource dictionary. Output files are named {prefix}-part1.pdf, {prefix}-part2.pdf, … auto-zero-padded when there are ≥10 parts.

SHELL — CLI 
# Strategy 1 — one output file every 5 pages
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --split --input report.pdf \
  --every-n-pages 5 --output-dir split/

# Strategy 2 — divide into 4 roughly equal parts
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --split --input report.pdf \
  --into-parts 4 --output-dir split/

# Strategy 3 — explicit page boundaries
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --split --input report.pdf \
  --page-ranges "1-3,4-6,7-10" --output-dir split/

# Split a password-protected PDF
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --split --input protected.pdf \
  --password secret --every-n-pages 3 --output-dir split/
FlagDefaultDescription
--inputrequiredPath to the PDF to split
--output-dirsplit-output/Directory for output files (created if absent)
--prefixinput stemFilename prefix. "report.pdf" → prefix "report" → report-part1.pdf
--every-n-pages—Fixed chunk size. The last chunk may be smaller than N.
--into-parts—Number of equal parts. Earlier parts receive one extra page when the total does not divide evenly.
--page-ranges—Explicit ranges: "1-3,4-6,7-10". Both bounds are 1-based and inclusive.
--passwordnonePassword for encrypted source PDFs
JAVA — all three strategies 
import com.pdfcreator.manipulator.*;

PdfManipulator manip = new PdfManipulator();

// Strategy 1
SplitResult r = manip.split(new SplitOptions.Builder("report.pdf", "split/")
    .everyNPages(5).build());

// Strategy 2
SplitResult r = manip.split(new SplitOptions.Builder("report.pdf", "split/")
    .intoParts(4).build());

// Strategy 3
SplitResult r = manip.split(new SplitOptions.Builder("report.pdf", "split/")
    .byPageRanges(new int[][]{ {1,3}, {4,6}, {7,10} }).build());

// Inspect result
System.out.printf("Split %d pages into %d files%n",
    r.getTotalPagesProcessed(), r.getOutputCount());
r.getOutputPaths().forEach(System.out::println);
✓ SplitResult provides getOutputPaths(), getPageCounts(), getOutputCount(), and getTotalPagesProcessed()
Printing

Send a PDF to a physical printer using the standard Java Printing API. Supports page ranges, duplex modes, scaling, copies, and both interactive (dialog) and silent (headless/batch) modes.

20
List Printers
Discover all printers registered with the OS — no PDF input required

Uses javax.print.PrintServiceLookup.lookupPrintServices() to query the OS print spooler (Windows print queue or CUPS on Linux/macOS). The default printer is marked with a <-- default indicator.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar --list-printers
EXPECTED CONSOLE OUTPUT 
=======================================================
  Available Printers
=======================================================
  [1] Microsoft Print to PDF  <-- default
  [2] HP LaserJet 400 M401dn
  [3] Brother HL-L2350DW series
=======================================================
  Total: 3 printer(s)
  Default: Microsoft Print to PDF
=======================================================
JAVA — programmatic API 
import com.pdfcreator.printer.*;

PdfPrinter printer = new PdfPrinter();

List<String> names = printer.listPrinters();
names.forEach(System.out::println);

String def = printer.getDefaultPrinterName(); // null if none configured
21
Print to Printer
Silent, dialog, duplex, page range, copies — full print job control

The printing pipeline: PDFPrintTree (PDFBox's Pageable) renders each PDF page onto the Graphics2D surface provided by the printer driver at the printer's native resolution (typically 600dpi). Job attributes (Copies, PageRanges, Sides, JobName) are passed via a HashPrintRequestAttributeSet. No intermediate image files are written.

SHELL — CLI 
# Print to the default printer — shows OS dialog for confirmation
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --print --input report.pdf

# Silent print (no dialog) to a named printer
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --print --input report.pdf \
  --printer "HP LaserJet 400 M401dn" --silent

# 2 copies, pages 2–5, duplex long edge, shrink-to-fit scaling
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --print --input    report.pdf \
  --printer          "HP LaserJet 400 M401dn" \
  --copies           2 \
  --start-page       2 \
  --end-page         5 \
  --sides            duplex-long \
  --scaling          shrink \
  --silent

# Print a password-protected PDF
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --print --input protected.pdf --password secret --silent
FlagDefaultDescription
--inputrequiredPath to the PDF to print
--printersystem defaultExact printer name from --list-printers. Matching is case-insensitive.
--copies1Number of copies
--start-page1First page to print (1-based)
--end-pagelastLast page to print (1-based, inclusive)
--sidessimplexsimplex · duplex-long (portrait binding) · duplex-short (landscape binding)
--scalingfitfit (scale up or down) · shrink (scale down only) · actual (72dpi, no scaling)
--silentoffSkip the OS print dialog. Required for headless / server-side / batch printing.
--passwordnonePassword for encrypted PDFs. Permission check uses canPrint().
--job-namefilename stemJob name shown in the OS print queue and on the printer's front panel
JAVA — programmatic API 
import com.pdfcreator.printer.*;
import java.awt.print.PrinterException;

PdfPrinter printer = new PdfPrinter();

// Convenience — print to default printer, silent, all defaults
printer.printDefault("report.pdf");

// Full options
PrintOptions opts = new PrintOptions.Builder("report.pdf")
    .printerName("HP LaserJet 400 M401dn")
    .startPage(2).endPage(5)
    .copies(2)
    .sides(PrintOptions.Sides.DUPLEX_LONG_EDGE)
    .scaling(PrintOptions.ScalingMode.SHRINK)
    .silent(true)
    .jobName("Q1 Report")
    .build();

try {
    printer.print(opts);
} catch (PasswordRequiredException e) {
    System.err.println(e.wasPasswordProvided() ? "Wrong password" : "Password required");
} catch (PrinterException e) {
    System.err.println("Printer error: " + e.getMessage());
    // Use --list-printers to verify the printer name
}
💡 Printer name matching is case-insensitive. Use --list-printers to get the exact OS name, then pass it to --printer or printerName(). If omitted, the system default printer is used automatically.
✓ Job submitted to the OS print queue — visible in the OS printer dialog or CUPS queue until the printer processes it
