Encryption & Permissions

AES-256 encryption and permission management via PDFBox's StandardProtectionPolicy. Every encrypted PDF carries two passwords: a user password (needed to open) and an owner password (full control, change permissions). Both can be the same string.

Encrypt

bash
# Encrypt with a named permission preset
java -jar pdf-creator.jar --encrypt \
  --input          report.pdf \
  --output         report-enc.pdf \
  --owner-password admin456 \
  --user-password  view123 \
  --permissions    FILL_AND_PRINT

# Encrypt with individual deny flags
java -jar pdf-creator.jar --encrypt \
  --input          report.pdf \
  --output         report-enc.pdf \
  --owner-password secret \
  --user-password  view \
  --deny-modify --deny-extract

Decrypt & inspect

bash
# Decrypt (owner password required)
java -jar pdf-creator.jar --decrypt \
  --input          report-enc.pdf \
  --output         report-plain.pdf \
  --owner-password admin456

# Inspect any encrypted PDF — no password needed if user password is empty
java -jar pdf-creator.jar --inspect-security \
  --input          report-enc.pdf

# Supply --owner-password only when a user password is also set
java -jar pdf-creator.jar --inspect-security \
  --input          report-enc.pdf \
  --owner-password admin456

Digital Signatures

PKCS#7/CMS detached signatures using adbe.pkcs7.detached — the format supported by Adobe Acrobat and all major PDF viewers. The signature is embedded as an incremental revision; the original byte ranges are never modified.

Sign

bash
# Invisible signature with RFC 3161 TSA timestamp
java -jar pdf-creator.jar --sign \
  --input             statement.pdf \
  --output            statement-signed.pdf \
  --keystore          bank.p12 \
  --keystore-password secret \
  --reason            "Monthly Account Statement" \
  --location          "Mumbai, India" \
  --tsa-url           http://timestamp.digicert.com

# Visible signature box on page 1
java -jar pdf-creator.jar --sign \
  --input             contract.pdf \
  --output            contract-signed.pdf \
  --keystore          signing.p12 \
  --keystore-password secret \
  --visible --sig-page 1 \
  --sig-x 50 --sig-y 50 --sig-width 200 --sig-height 60

Verify & export certificate

bash
# Verify against JVM default trust (commercial CA certs)
java -jar pdf-creator.jar --verify --input statement-signed.pdf

# Verify with a custom trust anchor (self-signed or internal CA)
java -jar pdf-creator.jar --verify \
  --input      statement-signed.pdf \
  --truststore bank-public.cer

# Export the signing certificate from a keystore
java -jar pdf-creator.jar --export-cert \
  --keystore          bank.p12 \
  --keystore-password secret \
  --output            bank-public.cer

Generate a test keystore with keytool

bash — keytool
keytool -genkeypair \
  -storepass  changeit \
  -storetype  PKCS12 \
  -alias      myorg \
  -validity   365 \

  -keysize    2048 \

  -keystore   myorg.p12

Generating PDF/A-1b Documents

Add --pdfa to any generation command to produce an ISO 19005-1 Level B compliant document. The pipeline saves with CompressParameters.NO_COMPRESSION (avoiding forbidden cross-reference streams) and attaches all four required XMP metadata schemas: DublinCore, AdobePDF, XMPBasic, and PDFAIdentification.

Template mode

bash
java -jar pdf-creator.jar \
  --template-id bank-statement \
  --data-file   data/statements/statement-001.json \
  --output      output/statement-001.pdf \
  --pdfa
console output
Template : bank-statement — Monthly Account Statement
PDF/A-1b : compliance markers attached
Pages    : 3 → output/statement-001.pdf

Batch mode

bash
java -jar pdf-creator.jar \
  --batch --template-id bank-statement \
  --data-dir   data/statements/ \
  --output-dir output/statements/ \
  --threads 8 --pdfa

Batch + sign in one pass

bash
java -jar pdf-creator.jar \
  --batch --template-id bank-statement \
  --data-dir          data/statements/ \
  --output-dir        output/signed/ \
  --threads 4 --pdfa --sign \
  --keystore          bank.p12 \
  --keystore-password secret \
  --reason            "Monthly Account Statement" \
  --tsa-url           http://timestamp.digicert.com
ℹ
Each PDF is generated → PDF/A markers are attached → it is digitally signed — all in the same pipeline pass. The unsigned intermediate file is never written to disk.
⚠
PDF/A is incompatible with AcroForm interactive fields. ISO 19005-1 §6.1.3 forbids interactive features. To archive a filled form, fill and flatten it first (--fill-form --flatten), then validate with --validate-pdfa. See §10–11.

Validating PDF/A Compliance

Runs the PDFBox Preflight engine — a syntax check during parsing, then a full ISO 19005 semantic rule check on the parsed document tree.

bash
# Basic validation — print result to stdout
java -jar pdf-creator.jar --validate-pdfa --input statement.pdf

# Write JSON report to file
java -jar pdf-creator.jar --validate-pdfa \
  --input  statement.pdf \
  --output validation-report.json

# Validate against PDF/A-1a (stricter accessibility rules)
java -jar pdf-creator.jar --validate-pdfa \
  --input    report.pdf \
  --standard pdf-a-1a

# Cap errors at 20 (useful for large noisy batches)
java -jar pdf-creator.jar --validate-pdfa \
  --input      large-report.pdf \
  --max-errors 20

invalid document

Exit codes — for CI/CD scripts

0Document is valid — no conformance issues
1Document is invalid — one or more issues found
2Error — file not found, unreadable, or unknown --standard value
bash — CI/CD
# Fail the build if the PDF is not compliant
java -jar pdf-creator.jar --validate-pdfa --input output/statement.pdf
if [ $? -ne 0 ]; then echo "validation failed"; exit 1; fi

# Validate all PDFs in a directory
for f in output/*.pdf; do
  java -jar pdf-creator.jar --validate-pdfa --input "$f" --max-errors 5
done

# Inline pass/fail
java -jar pdf-creator.jar --validate-pdfa --input out.pdf && echo PASS || echo FAIL

PDF/A and Other Operations

Merge — compliance preserved automatically

When at least one input to --merge is PDF/A, the output automatically receives compliance markers and the sRGB output intent.

bash
java -jar pdf-creator.jar --merge \
  --input  cover.pdf body.pdf appendix.pdf \
  --output merged.pdf
java -jar pdf-creator.jar --validate-pdfa --input merged.pdf

Split — compliance preserved automatically

Each part produced by --split inherits PDF/A markers from the source document.

bash
java -jar pdf-creator.jar --split \
  --input          annual-report-pdfa.pdf \
  --output-dir     parts/ \
  --split-mode     every-n \
  --pages-per-part 5
java -jar pdf-creator.jar --validate-pdfa --input parts/part-001.pdf

Encryption vs signing compatibility

OperationPDF/A-1b Compatible?Notes
--encrypt❌ No — error [8.1]Encryption is forbidden by ISO 19005-1. PdfCreator warns but does not block the operation.
--sign✅ Yesadbe.pkcs7.detached is the approved PDF/A-1 signature subfilter. Applied as an incremental revision.

PDF/A Error Code Reference

CodeCategoryCommon Cause & Fix
[1.4]Cross-reference streamsPDF 1.5+ xref streams present (forbidden under PDF/A-1b). Fix: save with CompressParameters.NO_COMPRESSION.
[2.x]Graphics / ColourDeviceRGB or CMYK used without an sRGB output intent ICC profile.
[3.1.3]FontsNon-embedded font — the most common failure when generating without --pdfa.
[3.1.x]FontsMissing FontDescriptor or missing ToUnicode map.
[4.x]TransparencySMask, blend modes, or alpha compositing — forbidden in PDF/A-1.
[5.x]AnnotationsForbidden annotation types, e.g. FileAttachment, Movie.
[6.x]ActionsJavaScript, GoToRemote, Launch, or URI actions are forbidden.
[7.1]Metadata / XMPXMP stream absent or structurally invalid. Fix: attach all four required XMP schemas.
[7.2]Metadata syncInfo dict values not mirrored to XMP. Fix: sync Subject → dc:description; read ModDate back from the info dict — do not call Calendar.getInstance() independently.
[7.11]PDF/A ID schemaMissing pdfaid:part / pdfaid:conformance. Fix: attach PDFAIdentificationSchema with part=1, conformance=B.
[8.1]EncryptionAlways forbidden. Distribute unencrypted PDF/A files with access controls at system or portal level.

Generate Form

Creates a new PDF with interactive AcroForm fields from scratch. No template file required — fields are defined entirely via repeatable --field arguments using a comma-separated spec format.

Full example with all field types

bash
java -jar pdf-creator.jar --generate-form \
  --output output/loan-application.pdf \
  --title  "Loan Application Form" \
  --field "name=fullName,type=text,label=Full Name,required,tooltip=Enter your legal name" \
  --field "name=email,type=text,label=Email Address,required" \
  --field "name=address,type=multiline,label=Residential Address,rows=3" \
  --field "name=loanType,type=combo,label=Loan Type,options=Personal|Home|Auto|Education,default=Personal" \
  --field "name=repayment,type=radio,label=Repayment Frequency,options=Monthly|Quarterly|Annual" \
  --field "name=branch,type=listbox,label=Preferred Branch,options=Chennai|Mumbai|Delhi|Bangalore" \
  --field "name=consent,type=checkbox,label=I agree to the terms,default=Yes" \
  --field "name=notes,type=multiline,label=Additional Notes,rows=4,readonly"

Field types

type=PDFBox ClassDescription
textPDTextFieldSingle-line text input
multilinePDTextField (multiline=true)Multi-line text area — height auto-calculated from rows=
checkboxPDCheckBoxOn/off toggle — default=Yes pre-checks it
radioPDRadioButtonMutually exclusive group — one widget per option, stacked vertically
comboPDComboBoxDrop-down selector — requires options=
listboxPDListBoxScrollable list — requires options=

Field spec keys

name=<n>required
AcroForm partial field name. Must be unique within the form.
type=<t>required
text · multiline · checkbox · radio · combo · listbox
label=<text>optional
Human-readable label printed above the widget.
requiredflag
Sets PDF Required flag. Displayed with * in the rendered form.
readonlyflag
Sets ReadOnly flag. Field is visible but not editable.
default=<v>optional
Initial value. Use "Yes" to pre-check a CHECKBOX.
options=<a|b|c>req for radio/combo/listbox
Pipe-separated selectable options.
tooltip=<text>optional
Widget tooltip stored in annotation Contents entry.
rows=<n>optional
MULTILINE / LISTBOX: visible rows. Default: 3.
height=<pts>optional
Widget height in points. 0 = auto-calculated.
toggleSize=<pts>optional
CHECKBOX / RADIO: widget square size. Default: 12 pt.

Extract Form

Reads all AcroForm fields from an existing PDF using a depth-first getFieldIterator() traversal — correctly discovers nested fields like address.city that getFields() would miss. Output is JSON. Omit --output to print to stdout, enabling piping to other tools.

bash
# Print JSON to stdout
java -jar pdf-creator.jar --extract-form --input output/loan-application.pdf

# Write to file
java -jar pdf-creator.jar --extract-form \
  --input  output/loan-application.pdf \
  --output output/loan-fields.json

# Password-protected PDF
java -jar pdf-creator.jar --extract-form \
  --input    output/loan-secured.pdf \
  --output   output/loan-fields.json \
  --password s3cr3t

JSON output format

json
{
  "sourcePath":     "output/loan-application.pdf",
  "hasAcroForm":    true,
  "totalFields":    8,
  "fillableFields": 8,
  "durationMs":     34,
  "fields": [
    {
      "partialName":        "loanType",
      "fullyQualifiedName": "loanType",
      "fieldType":          "COMBO",
      "currentValue":       "Personal",
      "required":           false,
      "readOnly":           false,
      "tooltip":            null,
      "options":            ["Personal", "Home", "Auto", "Education"]
    }
  ]
}
ℹ
Field types PUSHBUTTON and SIGNATURE appear in extraction output but are not fillable — PdfFormFiller rejects any attempt to set values on them. hasAcroForm: false means the PDF has no interactive form at all.

Fill Form

Fills field values into an existing AcroForm and writes to a new file. The source PDF is never modified. Fields are resolved by fully-qualified name first, then partial name as fallback — so city matches address.city when unambiguous.

Fill and keep editable

bash
java -jar pdf-creator.jar --fill-form \
  --input  output/loan-application.pdf \
  --output output/loan-filled.pdf \
  --field "name=fullName,value=Arjun Kumar" \
  --field "name=email,[email protected]" \
  --field "name=loanType,value=Home" \
  --field "name=repayment,value=Monthly" \
  --field "name=consent,value=Yes"

Fill and flatten (static, archival-ready output)

bash
java -jar pdf-creator.jar --fill-form \
  --input  output/loan-application.pdf \
  --output output/loan-final.pdf \
  --field "name=fullName,value=Arjun Kumar" \
  --field "name=loanType,value=Home" \
  --field "name=consent,value=Yes" \
  --flatten
⚠
--flatten invalidates digital signatures. PdfFormFiller warns if signature fields are present. Only flatten when producing a final archival or print copy.

Value format per field type

Field TypeValue to SupplyNotes
TEXT / MULTILINEAny stringMulti-line values may include \n
CHECKBOX"Yes" / "true" / "on" / "1" → checkedCase-insensitive. Anything else → unchecked.
RADIOExact export value from options listMust match one of the options[] values from extraction output. Invalid value → error, field is left unchanged.
COMBO / LISTBOXExact option display valuePDComboBox with isEdit()=true also accepts free-text values not in the list.

Quick Reference — Part 2

bash — security

# Generate PDF/A-1b
java -jar pdf-creator.jar --template-id <id> --data-file <json> --output <pdf> --pdfa
# Validate
java -jar pdf-creator.jar --validate-pdfa --input <pdf>
# Validate all PDFs, write reports
for f in output/*.pdf; do java -jar pdf-creator.jar --validate-pdfa --input "$f"; done

java -jar pdf-creator.jar --validate-pdfa --input out.pdf && echo PASS || { echo FAIL; exit 1; }

# Generate blank form
java -jar pdf-creator.jar --generate-form --output <pdf> --title <text> --field "name=<n>,type=<t>,label=<l>"
# Inspect fields
java -jar pdf-creator.jar --extract-form --input <pdf> [--output fields.json]

# Validate flattened form
java -jar pdf-creator.jar --validate-pdfa --input <final.pdf>
