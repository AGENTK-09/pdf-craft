Direct Mode

Generate a PDF quickly from a title, author, and body text — no template file required. Best for meeting notes, quick reports, and ad-hoc documents.

01
Inline Title & Text
Pass the document body directly on the command line

Supply all content as CLI arguments. Multi-paragraph body text uses \n\n as a paragraph separator. The renderer word-wraps automatically.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --title  "Meeting Notes — Q1 2026" \
  --author "Jane Smith" \
  --text   "Attendees: Jane Smith, Robert Jones, Priya Patel.\n\nKey decisions: approved Q1 budget, deferred platform migration to Q2, agreed fortnightly standups.\n\nActions: Jane to circulate revised budget by Friday. Robert to produce migration risk assessment by end of month." \
  --output output/01-direct-inline.pdf
✓ Produces: 01-direct-inline.pdf — single page with heading, author line, and wrapped body paragraphs
02
Text from File
Read body content from a .txt file on disk

When body text is long or pre-authored, point --text-file at a plain text file. Use blank lines in the file for paragraph breaks. Auto-pagination kicks in if text overflows a page.

PLAIN TEXT — body.txt 
This is paragraph one. It contains enough content to demonstrate proper word
wrapping behaviour across the full usable page width.

This is paragraph two. The body renderer inserts a blank line between
paragraphs wherever a newline character appears in the source text.

This is paragraph three. A new page starts automatically when the cursor
reaches the bottom margin.
SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --title     "Report from File" \
  --text-file body.txt \
  --output    output/02-direct-from-file.pdf
✓ Produces: 02-direct-from-file.pdf — paginated document from file content
03
Custom Config Preset
Override fonts, margins, and colors with a named config

Each config preset in configs/pdf-configs.json defines a complete visual style. Pass --config-id to switch between them. Available presets: default, report, letter, compact, banking, dark.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --config-id report \
  --title     "Q4 Executive Summary" \
  --text      "Revenue exceeded targets by 12% in Q4. Operating costs remained within budget. The board approved the proposed expansion into three new markets for FY2027." \
  --output    output/03-direct-report-config.pdf
ℹ The report preset uses wider margins (72pt), larger title font (24pt), and dark blue title color (#003366) vs the 50pt margins and 20pt titles of the default preset.
✓ Produces: 03-direct-report-config.pdf — styled with the report preset's fonts and spacing

Template Mode

Combine a template definition (templates/pdf-templates.json) with a JSON data file. Templates define layout, branding, section types, and placeholder keys. Data files supply the runtime values.

04

Columns layout · transaction table · summary · footer with page numbers

07
Missing Placeholder Warning
Graceful handling — renders successfully with a warning, not a crash

If the data file omits a key that a template references, the placeholder is left blank in the output and a warning is printed to stderr. The render does not throw an exception. This is the correct production behaviour — partial data still produces a PDF.

JAVA — programmatic (via RenderPipeline) 
import com.pdfcreator.datasource.*;
import com.pdfcreator.pipeline.RenderPipeline;

// Load full data then intentionally drop one key
DocumentData fullData = new JsonFileDataSource("data/statements/CUST-002.json").load();

DocumentData.Builder builder = new DocumentData.Builder();
fullData.getScalars().forEach((k, v) -> {
    if (!k.equals("closing_balance")) builder.scalar(k, v); // omit one key
});
fullData.getLists().forEach(builder::list);
DocumentData trimmedData = builder.build();

RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);

// Renders successfully — {{closing_balance}} appears blank in output
// stderr prints: Warning: Unresolved placeholders: [closing_balance]
pipeline.render(
    "bank-statement",
    new InMemoryDataSource(trimmedData, "CUST-002 trimmed"),
    "output/07-missing-placeholder.pdf"
);
⚠ Expected stderr output: Warning: Unresolved placeholders (no value in data file): [closing_balance]. The PDF is still written to disk.
✓ Produces: 07-missing-placeholder.pdf — renders with blank where closing_balance would appear
Batch Mode

Generate thousands of PDFs in parallel from a directory of JSON files or a CSV. A shared RenderPipeline is reused across jobs; each job gets its own PDDocument.

08
Directory Source — Parallel
One JSON file per customer → one PDF each, 4 threads

Drop one .json data file per customer into a directory. DirectoryBatchJobFactory discovers them all and creates one BatchJob per file. BatchRunner executes them in parallel using a fixed thread pool.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --batch \
  --template-id bank-statement \
  --data-dir    data/statements/ \
  --output-dir  output/batch-statements/ \
  --threads     4
JAVA — programmatic (direct API) 
import com.pdfcreator.batch.*;
import com.pdfcreator.pipeline.RenderPipeline;
import java.util.List;

RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);

// Discover all .json files in data/statements/
List<BatchJob> jobs = new DirectoryBatchJobFactory(
    "bank-statement",        // template ID
    "data/statements",        // input directory
    "output/batch-statements" // output directory
).createJobs();

// Run with 4 parallel threads
List<BatchResult> results = new BatchRunner(pipeline, 4).run(jobs);

// Print summary
long ok = results.stream().filter(BatchResult::isSuccess).count();
System.out.printf("%d OK, %d FAILED%n", ok, results.size() - ok);
EXPECTED CONSOLE OUTPUT 
Batch run: 2 jobs, 4 thread(s)
Template : bank-statement — Monthly bank account statement
...
Pages: 2 → output/batch-statements/CUST-001.pdf
Pages: 2 → output/batch-statements/CUST-002.pdf

════════════════════════════════════════════════════════════
Batch complete: 2 OK, 0 FAILED, total 1.2s
────────────────────────────────────────────────────────────
  OK   [ 623ms] CUST-001
  OK   [ 589ms] CUST-002
════════════════════════════════════════════════════════════
✓ Produces: CUST-001.pdf, CUST-002.pdf in output/batch-statements/ — generated in parallel
09
CSV Source — Parallel
One CSV row per customer → one PDF each, 3 threads

When each document only needs scalar data (no transaction tables), a CSV is more convenient than individual JSON files. Each row becomes one InMemoryDataSource internally — no temp files are created. Column headers become data keys. Specify which columns hold the reference ID and output filename with --ref-col / --out-col.

SHELL — CLI 
java -jar target/pdf-creator-1.0-SNAPSHOT.jar \
  --batch \
  --template-id notification-letter \
  --csv-file    data/notifications.csv \
  --output-dir  output/batch-notifications/ \
  --ref-col     ref_id \
  --out-col     output_file \
  --threads     3
CSV — data/notifications.csv (first two rows) 
ref_id,output_file,bank_name,customer_name,customer_address_line1,...,salutation,...
NOTIF-001,NOTIF-001.pdf,National Bank plc,Jane Smith,42 Maple Avenue,...,Ms Smith,...
NOTIF-002,NOTIF-002.pdf,National Bank plc,Robert Jones,17 Oak Street,...,Mr Jones,...
NOTIF-003,NOTIF-003.pdf,National Bank plc,Priya Patel,8 River Road,...,Ms Patel,...
JAVA — programmatic (direct API) 
RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);

List<BatchJob> jobs = new CsvBatchJobFactory(
    "notification-letter",           // template ID
    "data/notifications.csv",         // CSV file path
    "output/batch-notifications",     // output directory
    "ref_id",                         // column used as reference ID in logs
    "output_file"                     // column used as output filename
).createJobs();

List<BatchResult> results = new BatchRunner(pipeline, 3).run(jobs);
✓ Produces: NOTIF-001.pdf, NOTIF-002.pdf, NOTIF-003.pdf in output/batch-notifications/
10
Batch — Single Thread (Serial)
Set --threads 1 for deterministic ordering or resource-constrained environments

Identical to scenario 08 but with --threads 1. Jobs execute sequentially in input order. Useful for debugging, or when the host machine has limited memory.

SHELL — CLI

  --batch \
  --template-id bank-statement \
  --data-dir    data/statements/ \
  --output-dir  output/batch-statements/serial/ \

List<BatchResult> results = new BatchRunner(pipeline, 1).run(jobs);
// Jobs run one at a time, in the order returned by createJobs()
✓ Same output as scenario 08 — files produced sequentially rather than in parallel
Programmatic API

Use RenderPipeline directly from Java code when data comes from a database, REST API, or is assembled in memory — with no intermediate files.

11
InMemoryDataSource
Build DocumentData in code — no files, no network, no database

Construct a DocumentData object directly in Java and wrap it in an InMemoryDataSource. The pipeline doesn't know or care where the data came from. Ideal for integration with Spring services, JDBC repositories, or unit tests.

JAVA — full example 
import com.pdfcreator.datasource.*;
import com.pdfcreator.pipeline.RenderPipeline;
import java.util.*;

// Build transaction rows in memory
List<Map<String, String>> txns = List.of(
    Map.of("date", "01 Mar", "type", "SO",   "description", "RENT PAYMENT",
           "debit", "950.00", "credit", "", "balance", "2050.00"),
    Map.of("date", "03 Mar", "type", "BACS", "description", "SALARY ACME LTD",
           "debit", "", "credit", "3200.00", "balance", "5250.00"),
    Map.of("date", "05 Mar", "type", "POS",  "description", "WAITROSE",
           "debit", "87.34", "credit", "", "balance", "5162.66"),
    Map.of("date", "07 Mar", "type", "ATM",  "description", "CASH WITHDRAWAL",
           "debit", "200.00", "credit", "", "balance", "4962.66"),
    Map.of("date", "10 Mar", "type", "DD",   "description", "COUNCIL TAX",
           "debit", "178.00", "credit", "", "balance", "4784.66")
);

// Assemble complete DocumentData using the builder
DocumentData data = new DocumentData.Builder()
    .scalar("bank_name",             "Test Bank plc")
    .scalar("reg_no",                "99999999")
    .scalar("fca_no",                "654321")
    .scalar("customer_name",         "Test Customer")
    .scalar("customer_address_line1", "1 Test Street")
    .scalar("customer_address_line2", "Testville")
    .scalar("customer_postcode",      "TE1 1ST")
    .scalar("account_no",            "00000001")
    .scalar("sort_code",             "00-00-00")
    .scalar("statement_date",        "31 March 2026")
    .scalar("period_from",           "01 March 2026")
    .scalar("period_to",             "31 March 2026")
    .scalar("opening_balance",       "£2,000.00")
    .scalar("total_credits",         "£3,200.00")
    .scalar("total_debits",          "£1,415.34")
    .scalar("closing_balance",       "£3,784.66")
    .list("transactions", txns)
    .build();

// Render — zero file I/O for data
RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);
pipeline.render(
    "bank-statement",
    new InMemoryDataSource(data, "programmatic test customer"),
    "output/11-inmemory-datasource.pdf"
);
💡 For database-backed generation, replace InMemoryDataSource with JdbcDataSource — pass a connection pool supplier and SQL queries. The pipeline call stays identical.
✓ Produces: 11-inmemory-datasource.pdf — full bank statement rendered from in-memory data
Error Handling

Both failure modes throw clearly typed exceptions. Wrap pipeline.render() in a try-catch in production code. In batch mode, failures are isolated per job — one bad job does not abort the run.

12
Missing Data File
Expects IOException — file not found
JAVA — catching IOException 
RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);

try {
    pipeline.render(
        "bank-statement",
        new JsonFileDataSource("data/does-not-exist.json"), // ← bad path
        "output/12-should-not-be-created.pdf"
    );
} catch (IOException e) {
    // ✓ Expected: "Data file not found: data/does-not-exist.json"
    System.err.println("Caught expected IOException: " + e.getMessage());
}
⚠ Expected exception message: Data file not found: data/does-not-exist.json. No output file is created.
13
Non-existent Template ID
Expects RuntimeException — template not found in registry
JAVA — catching RuntimeException 
RenderPipeline pipeline = new RenderPipeline(
    "templates/pdf-templates.json",
    "configs/pdf-configs.json"
);

try {
    pipeline.render(
        "no-such-template",                   // ← bad template ID
        new JsonFileDataSource("data/statements/CUST-001.json"),
        "output/13-should-not-be-created.pdf"
    );
} catch (RuntimeException e) {
    // ✓ Expected: "Template not found: no-such-template"
    System.err.println("Caught expected RuntimeException: " + e.getMessage());
}
⚠ Expected exception message: Template not found: no-such-template. Check that the template ID exactly matches an entry in pdf-templates.json.
